# ADR-0001：使用 gRPC + 关系型数据库，替代 gRPC + LevelDB

- 状态：已接受
- 日期：2026-10-20

## 背景

一个早期原型使用 gRPC + LevelDB。LevelDB 是嵌入式键值存储：数据目录由单个进程独占，没有复制、没有多实例访问，也没有服务端。这意味着无法让多个 signer 实例共享同一份数据，也难以实现高可用、时间点备份以及密钥生命周期操作所需的事务保证。

signer 是低频写、强一致的服务，需求本质是高可用，而不是吞吐量。

## 决策

- 服务协议继续使用 gRPC，基于 `tonic` 实现。
- 集群部署使用 PostgreSQL 作为主存储后端。
- 单机开发使用 SQLite 后端。
- 两者统一在 `KeyStore` trait 之后，其余代码与存储实现无关。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 继续用 LevelDB | 无复制、单进程、无事务 |
| RocksDB | 仍是嵌入式；解决性能，不解决高可用 |
| etcd | 强一致，但不适合存密钥数据块；运维成本高 |
| TiKV / CockroachDB | 分布式复杂度远超当前负载所需 |

## 影响

- 正面：具备多实例部署、事务、唯一约束、行锁、备份与故障切换能力。
- 正面：存储抽象让领域逻辑可测试，也为未来的 HSM/KMS 后端留出空间。
- 负面：集群部署多了一个 PostgreSQL 运维依赖。
- 负面：嵌入式与网络后端都要维护，必须补充契约测试。
